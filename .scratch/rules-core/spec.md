# Ядро правил боя

Status: ready-for-agent

## Problem Statement

Игроки Faenwald ведут феодальную игру во внешней таблице, а сражения отсуживают вручную.
Именно на отсуде и возникают жалобы на несправедливость — та самая проблема, ради которой
и написана статья «[CF] Боевая система»: она стремится к очевидности и проверяемости
исхода при минимальном судейском факторе. Но правил в ней много, они перемножаются, и
считать их руками ошибочно и утомительно.

Существующий прототип `faenwald-battle-prototyp-v2` эту задачу не решает: он реализует
собственный набор правил, местами прямо противоречащий статье, и стирает различия между
Родами войск, ради которых система и написана. Вся его боевая логика лежит в глобальных
сигналах вперемешку с React, поэтому её нельзя ни проверить тестами, ни переиспользовать.

## Solution

Модуль, который знает правила боя целиком и не знает больше ничего: ни про отрисовку, ни
про сеть, ни про то, откуда берутся Составы. Он принимает намерение игрока, проверяет его
по статье и возвращает новое состояние Боя вместе с журналом событий.

Игрок видит на доске только законные действия, потому что их перечисляет то же ядро, что
их и исполняет. Партия целиком воспроизводится по зерну и журналу, поэтому спорный исход
можно переиграть и показать, а не пересказать.

## Implementation Decisions

Проектное решение целиком принято в этой сессии и опирается на `docs/adr/0001` (hotseat,
ядро без React), `docs/adr/0002` (канон — статья), `docs/adr/0003` (отменённые решения) и
`docs/adr/0004` (выведенное прочтение Контратаки). Перенос статьи с числами —
`.scratch/boevaya-sistema/spec.md`.

### Интерфейс модуля

Всё, что каллер обязан знать, — три функции и четыре типа.

```ts
function start(setup: Setup, policies: Policies, seed: number): BattleState
function apply(state: BattleState, intent: Intent): Applied
function legalIntents(state: BattleState): readonly Intent[]

type Applied =
  | { ok: true;  state: BattleState; events: readonly Event[] }
  | { ok: false; reason: Rejection }
```

`legalIntents` входит в интерфейс намеренно. Без неё модуль становится мелким: UI начнёт
сам вычислять достижимые Гексы и накрытые конусом цели, и правила расползутся по
компонентам — болезнь прототипа. `apply` — единственный вход: решение по Оппортуну и
выбор «применять ли Прорыв» такие же `Intent`, как шаг.

### Фаза как часть состояния

Оппортун вклинивается между объявлением действия и его исполнением, и решение внутри
прерывания принадлежит другому игроку. Поэтому «чьего решения ждут» — поле состояния, а
не поток управления:

```ts
type Phase =
  | { kind: 'turn';         squad: SquadId }
  | { kind: 'opportunity';  holders: readonly SquadId[]; against: SquadId; deferred: Intent }
  | { kind: 'breakthrough'; attacker: SquadId; target: SquadId }
  | { kind: 'rout';         squad: SquadId }
  | { kind: 'over';         report: BattleReport }
```

Колбэк или продолжение дали бы то же поведение, но не пережили бы сериализацию — а
`docs/adr/0001` требует, чтобы переход в сетевой PvP означал написание транспорта поверх
готового ядра, а не переписывание правил.

Протокол Оппортуна: шаг в Зону провокации **взводит** право держателю; следующее
объявленное намерение цели уходит в `deferred`, фаза становится `opportunity`; держатели
отвечают по очереди; после последнего исполняется `deferred`, если цель жива и не в
Бегстве. Исключение: если объявленное намерение — атака по самому держателю, она
исполняется первой. Право, никем не использованное, сгорает в конце Хода цели — правило
«не совершающий действий не провоцирует» выпадает из протокола само.

### Состояние

```ts
type BattleState = {
  readonly board:    Board      // Гексы, Местность, Уровень
  readonly catalog:  Catalog    // Типы отрядов
  readonly policies: Policies
  squads:  ReadonlyMap<SquadId, Squad>
  round:   number
  order:   readonly SquadId[]
  phase:   Phase
  rng:     RngState
  log:     readonly Event[]
}

type Squad = {
  id: SquadId; side: Side; type: SquadTypeId
  rank: number; headcount: number
  hex: Hex; facing: Facing
  health: number; morale: number
  movement: number            // остаток Запаса хода, дробный
  ammo: number
  chargeSteps: number
  threatArmed: readonly SquadId[]
  spent: { attacked: boolean; acted: boolean; surged: boolean; freeRotation: boolean }
  routing: boolean
  ruler: boolean
}
```

Три решения, которые стоит назвать вслух:

- **Генератор случайных чисел живёт внутри состояния.** В системе есть случайность — д3 на
  судьбу Правителя и проценты провала льда. Взятая снаружи, она лишила бы партию
  воспроизводимости по журналу, а с ней — и отладку, и будущий сетевой арбитраж.
- **Запас хода дробный.** Статья разрешает копить остаток меньше Гекса между Ходами, а
  Местность умножает затраты на 0,5 и 2.
- **Потери выводятся, а не хранятся.** Отнятое Здоровье — это `maxHealth - health`,
  лечения в Бою нет; отдельный счётчик стал бы вторым источником правды.

Характеристики каталога даны на сотню солдат и умножаются на `headcount / 100`.

### Швы

Шов заводится только там, где что-то действительно варьируется.

```ts
type Policies = {
  counterattackSpendsDefendersAttack: boolean
  opportunityZone: 'attackRange' | 'meleeOnly'
}
```

**Контратака** — настоящий шов: `docs/adr/0004` фиксирует прочтение как временное, и его
пункт «не тратит атаку защитника» из статьи не выводится вовсе. **Генератор случайных
чисел** — настоящий шов: детерминированный в тестах, засеянный в игре.

**Режимы атаки, Местность и Типы отрядов швами не являются** — это данные и внутренний
полиморфизм, наружу они не торчат. Прототип сделал `attack-strategies.ts` публичным и
получил интерфейс шире необходимого.

### Разрешение удара

Отдельная чистая функция со списком модификаторов на входе, а не цепочка ветвлений.
Порядок обязателен:

1. Базовый Урон Типа × `headcount / 100`.
2. Половина, если атакующий ниже половины Здоровья.
3. Перемножение модификаторов: Местность, Уровень, Сомкнутый строй, сторона, Таранный
   удар, «Тип против Типа».
4. Предельный урон ×3 от естественного — кроме морального урона кавалерии.
5. Округление до целого по правилам арифметики.
6. **Моральный урон, затем физический** — порядок, на котором держится Таранный удар.
7. Мораль достигла нуля — Бегство, Контратаки нет.
8. Контратака: ближний бой, во Фронт, защитник не в Бегстве.
9. Отражение Сомкнутого строя — работает и в Бегстве, атакой не считается.

### Фаза Бегства

Статья говорит «вы обязаны вывести его из боя по кратчайшему маршруту»: двигает игрок, но
маршрут ему не принадлежит. Фаза `rout` остаётся, ограничение живёт в `legalIntents` —
она возвращает только шаги по кратчайшему маршруту к ближайшему краю карты. Свободный
увод позволил бы перекрывать беглецом Гексы, то есть извлекать пользу из разгромленного
Отряда.

### Разложение

```
src/rules/
  index.ts            start / apply / legalIntents — единственный публичный файл
  state.ts            типы состояния и Фазы
  intent.ts           намерения и отказы
  turn-order.ts       Инициатива
  movement.ts         шаг, поворот, дробный запас, стоимость Местности
  attack.ts           режимы, дальность, конусы, линия
  damage.ts           конвейер из девяти шагов
  opportunity.ts      взведение и протокол прерывания
  breakthrough.ts     цепной сдвиг с откатом на Фланг и Фронт
  rout.ts             Бегство, мораль окружения, уход с карты
  report.ts           Потери и Отчёт о бое
```

Идентификаторы английские, понятия русские — соответствие задано в `CONTEXT.md`.

## Testing Decisions

Хорошим считается тест, который проверяет **правило из статьи**, а не устройство кода:
формулируется как «Отряд с такими характеристиками в такой позиции получает столько-то
урона», строится через публичные функции и остаётся зелёным при любой перетасовке файлов
внутри ядра.

Прототипа тестов в репозитории нет — код ещё не написан, тестовых прецедентов не
существует. Эта спека их и заводит.

**Швов три** (решение зафиксировано явно):

1. **Интерфейс ядра — основной шов.** Через `start`, `apply` и `legalIntents` проверяется
   всё поведение: очерёдность, перемещение, режимы стрельбы, протокол Оппортуна с
   передачей решения другой стороне, Контратака, Прорыв с цепным сдвигом, Бегство и уход
   с карты, Отчёт о бое. Сюда же ложится расчётный пример самой статьи — тяжёлые
   копейщики в Сомкнутом строю на холме против тяжёлой кавалерии в разбеге на предхолмье,
   с ожидаемыми 23 и 8. Он проверяет весь конвейер разом и взят из источника, а не
   придуман.
2. **Конвейер урона** — прямой шов на девятишаговый порядок модификаторов: перемножение,
   Предельный урон, округление, приоритет морального урона над физическим.
3. **Математика гексов** — прямой шов на odd-r: соседи, разбиение на Фронт, Фланг и Тыл,
   конус Навеса, расстояние.

Швы 2 и 3 прибиты к внутреннему разложению ядра: перенос кода между `damage.ts`, `hex.ts`
и соседями потребует правки тестов. Это принято сознательно ради точной адресации ошибок
в арифметике и в off-by-one, где падение на уровне интерфейса указывает на симптом, а не
на причину.

Отдельно проверяется **воспроизводимость**: одна и та же последовательность намерений при
одном зерне даёт одно и то же состояние, включая исходы бросков д3 и проверок льда.

И отдельно — **обе политики Контратаки**: набор тестов прогоняется при обоих значениях
`counterattackSpendsDefendersAttack`, чтобы ответ автора менял одну строку конфигурации, а
не половину набора.

## Out of Scope

- **Отрисовка, анимации, звук, UI.** Ядро не знает про React и не содержит ни координат в
  пикселях, ни таймингов.
- **Сеть, сервер, авторитетный арбитраж.** По `docs/adr/0001` версия делается hotseat;
  ядро лишь не закрывает дорогу в PvP.
- **Искусственный интеллект.** Оба Состава ведут люди.
- **Кампания, экономика, найм, Ранги как прогрессия.** Живут во внешней таблице; игра о
  ней не знает.
- **Медики и инженеры.** В Боях не участвуют по самой статье.
- **Осадные орудия, замки, фазы войны.**
- **Фаза выбора Состава и редактор сценариев.** Ядро принимает готовый `Setup`.
- **Индивидуальные шаблоны Отрядов.** Согласуются с Ординарием вне игры.

- **Два числовых расхождения внутри статьи**: Урон лучника 6 в таблице против 8 в разделе
  о Предельном уроне, и модификатор разбега ×1,48 в тексте против 1,5 в формуле примера.
  Второе задевает контрольный расчётный пример — тест на него должен ссылаться на этот
  вопрос, чтобы падение после ответа автора читалось как ожидаемое, а не как регрессия.

**Прототип не переиспользуется**, за одним исключением: математика гексов
(pointy-top, odd-r) в `hex-layout.ts` решает ту же задачу и её незачем выводить заново.
Боевая логика прототипа противоречит статье и не берётся.
